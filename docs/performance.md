# 行程加载性能

2026-09-14：针对 Docker / Nginx、3 Mbps 出口环境的优化。

## 数据加载

- 工作区使用 `GET /api/trips/:id?section=...`，各页面只读取所需集合。`plan` / `view` 保留候选路线摘要和步骤，不读取、解析或发送 `polyline`；费用页不查询路线。
- 地图单独请求 `GET /api/days/:id/geometry`，仅返回当前日期的已选路线坐标。客户端按日期 ID / version 复用缓存，忽略与当前日期版本不符的结果。
- 行程共享布局保留页面缓存与 SSE 连接，标签使用 Next.js 客户端导航。页面组件按需加载，费用页不必加载地图和拖拽编辑器代码。
- SSE 的初始 `sync`、重连以及 `change` 均携带变更序号。已包含该变更的快照不重复下载；下载期间出现新变更时追加刷新，避免漏更新。
- 保存操作使其他页面缓存失效。窗口获得焦点或重新进入缓存页面时先请求轻量的 `/revision`（包含成员昵称，兼容不产生行程动态的账号资料修改）；权限撤销清空缓存并取消正在进行的请求。
- 事项、交通、候选和费用分摊采用批量查询；快照用 SQLite deferred 只读事务，避免占用 writer lock。迁移 `0007_route_lookup_index` 增加 `(travelLegId, position)` 索引。

不传 `section` 的完整快照接口仍可用，API / MCP 的既有调用保留完整数据。各页面字段范围见 [API 文档](api.md#页面快照与按需地图)。

## 本地样本

独立临时数据库：7 天、28 段交通、84 个候选、29,400 个坐标点。无真实用户数据。以下为当前实现的原始 JSON 字节数；gzip 列是本机压缩结果，不能替代线上响应头或实际流量测量。

| 响应             |   原始 JSON |      gzip | 数据库查询数 |
| ---------------- | ----------: | --------: | -----------: |
| 完整快照         | 1,225,457 B | 204,035 B |           16 |
| 行程编辑         |    65,698 B |   2,939 B |           13 |
| 行程查看         |    65,443 B |   2,902 B |            8 |
| 费用             |    18,413 B |   1,189 B |           11 |
| 成员             |     2,950 B |     708 B |            7 |
| 动态             |     3,029 B |     792 B |            7 |
| 单日已选路线坐标 |    55,344 B |  13,688 B |            3 |

与下载完整快照相比，这个样本的行程编辑初始 JSON 缩小约 94.6%，费用页约 98.5%。具体比例取决于真实路线、账目和评论数量，不代表线上响应时间保证。优化前相同日程规模的完整快照查询为 60 次，现在为 16 次，且不再随天数、路段和费用笔数线性增加。

## 验证与部署

针对性测试：

```bash
npx vitest run tests/trip-store.test.ts tests/snapshot-performance.test.ts
npm run build
npx playwright test e2e/performance.spec.ts
```

单元测试覆盖传输期间的协作变更、写入后的刷新、缓存失效、权限撤销、晚到响应、地图版本，以及 SQLite 存在另一写事务时的可读性。浏览器测试使用生产构建，在初始快照延迟 800 ms 时验证单次请求，验证切页不重载文档或 SSE，并验证按日期加载坐标。

使用仓库自带 `compose.yaml` 在服务器更新代码后重新构建和启动：

```bash
docker compose up -d --build
```

Docker 入口脚本会应用新索引迁移。已有持久化卷保留；如果服务器使用预构建镜像，则需先构建并更新相应镜像版本。

部署后在浏览器 Network 中检查：

1. 费用页请求包含 `?section=expenses`，响应没有路线候选和坐标；首次加载只有一次页面快照请求。
2. 切换标签没有新的 document 请求，SSE 连接持续复用；切回未变更的页面不重复取快照。
3. 行程页通过 `/days/:id/geometry` 加载当前日期坐标，其他日期不会一起下载；步骤、路线切换和行程导出仍正常。
4. `Content-Encoding` 验证 JSON 是否实际被 gzip / Brotli 压缩。Next.js 默认压缩已启用；若 Nginx 接管压缩，需覆盖 `application/json`。不要缓存带会话权限的 API 响应。
5. 将慢请求的 `Server-Timing: app;dur=...` 与 Timing 中的等待首字节、下载时间对照。`app` 包含鉴权、业务处理与响应序列化，不含请求到达 handler 之前的排队或网络下载；`X-Request-Id` 可关联容器日志。
6. SSE 响应保持 `X-Accel-Buffering: no`，代理应允许持续流式传输。SSE 在 Network 中持续数十秒属于连接寿命，不能作为普通请求处理耗时。

服务器 CPU、内存和带宽的实际占用仍应在部署后测量；本地测试不替代线上验收。
